# 2026-10-26

## Owner test on the weak laptop (i5-7200U, 20 GB, Intel HD 620, 1366x768, Spec II only)

He played Time Trial Nordschleife (Nissan Motul Pitwork Z) in four configurations and sent the `Z:` share with the
sessions and the launcher logs. Findings, each with its evidence:

### 1. Vulkan loses the device (session-1792982511)
`vkQueueSubmit failed: (-4: VK_ERROR_DEVICE_LOST)` at 53 s, then `OSD [GSDeviceLost]`, then `[ee] halted: GS process
exited`; the launcher logged `ERROR graphics card lost: ... VK_ERROR_DEVICE_LOST` (issue #89 path). The HD 620 reports
**Vulkan 1.3**, so the automatic API plan picks Vulkan. Direct3D 11 runs the same build fine (all the runs after that).
**Not yet fixed:** the launcher names the loss but does not remember it; the next Play picks Vulkan again.

### 2. The launcher costs ~20% CPU in the background (biggest defect)
His Task Manager: `GT4Recomp.exe` at almost 20% of the i5 while the game ran, ~15% for the game; Windows "reduce motion"
(kills animations) dropped it below 1% and the game improved. Evidence in the F8 data: in session-1792983673 the **EE CPU**
itself is 19.61/19.16 ms (not waits), against 6-12 ms in the other runs: a 2-core U-series CPU starved by the launcher.
Cause in our UI: six full-screen background layers with `animation: bg-show 72s linear infinite, bg-pan 72s linear
infinite` (`ui/css/app.css:181`), plus `play-sheen` (3.4 s infinite) and a `setInterval` poll (`ui/pages/home.js:410`).
Hiding the window on Play (`tray.rs`) does not stop WebView2's animations. With GPU acceleration off (his test 4) the
transforms are painted on the CPU, which is why it was the same or worse.

### 3. False "crashed" on a normal close
The launcher logged `ERROR game ended: Crashed { reason: None, exit_code: Some(0) }` for sessions 1792983550, 1792983673
and 1792983709, while each log ends with `[ee] stopped after N frames, C cycles: window closed` and the GS exited 0. It
reads `game.log` in the same instant the game writes its last line (`commands.rs:501`), so `exit::classify` sees no
reason. The player gets the "stopped unexpectedly" dialog and the log-bundle offer for a normal close.

### 4. Render scale: 100% = 1x on the integrated GPU, then 125% jumps to 4x
`launcher-...log`: `display: 1366x768 -> 1x internal 640x448 (k 3, render scale 100%)` and `integrated GPU ...: default
internal 1x` (issue #89 rule). At 125% the rule no longer applies and `k x 125%` rounds to 4x (2560x1792); at 75%/50% it
rounds to 2x (1280x896, "a little less than the screen"). One notch from 100% quadruples the pixels. The owner's proposal:
100% should pull the slider to the smallest multiplier the screen allows (1x here) and the notches should be smooth.
Proposed mapping for TASK-118: **one 25% notch = one multiplier** from the plan's baseline (`baseline + (percent - 100) /
25`, clamped 1..12), so integrated 100/125/150/175/200% = 1/2/3/4/5x and a discrete 3x baseline gives 3/4/5/6/7x.
