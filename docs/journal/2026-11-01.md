## TASK-046: launcher "Prepare shaders" and pipeline cache warming roadmap

- Analyzed driver shader compilation spikes and cold-cache stalls documented in `docs/GS-LIVE.md` (section 9.3) and `docs/FRAME-COST-STUDY.md` (section 4.2).
- Identified root cause of in-race hitching: on-demand Vulkan/D3D12 pipeline compiles (`vkCreateGraphicsPipelines`) during synchronous EE readbacks (`download sync` for headlight flare intensity and occlusion queries), causing readback wait stalls of up to 58.0 ms (with 12 of 294 readbacks spiking $\ge 8\text{ ms}$).
- Confirmed cache warming efficacy: with a warmed `vulkan_pipelines.bin` cache, maximum readback wait drops from 58.0 ms to 2.7 ms, with zero spikes $\ge 8\text{ ms}$.
- Formulated the offline pipeline cache warming protocol:
  - Selector corpus: pre-extracted database of Gran Turismo 4's ~750 drawing context signatures (`gt4_pipeline_selectors.bin`, ~64-256 KB) extracted from headless race replays and menus.
  - Headless GS invocation: `gt4-gs.exe --warm-selectors <selectors.bin>` running in surfaceless mode, populating `[Folders] Cache / vulkan_pipelines.bin`.
  - Launcher integration: host driver fingerprint detection (`driver_fingerprint.json`) to detect vendor driver updates, optional background pre-warming, and a manual "Prepare shaders" action in Settings > Graphics.
  - Clean room & safety: complies strictly with Decision 0070 (no GPL code linked into launcher/game, executed via child process spawn with non-zero exit fault recovery).
