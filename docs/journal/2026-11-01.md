# 2026-11-01

## TASK-138: prevent audio crackling and underruns on Proton and SteamOS

- Authored comprehensive architecture and diagnostic study: [`docs/TASK-138-PROTON-AUDIO-CRACKLING-STUDY.md`](../TASK-138-PROTON-AUDIO-CRACKLING-STUDY.md).
- Diagnosed root cause of audio crackling/pops on continuous engine sounds reported in [Issue #129](https://github.com/moesuito/gt4-staticrecomp/issues/129):
  - In `native/host_io.cpp`, paced audio mode ran with fixed 60 ms target latency (`target_latency_frames = 2880`), sixteen 256-frame buffers (5.33 ms each), and a strict 58.6 ms queue cap (`(queued_device_buffers() + 1) * frames_per_buffer <= target_latency_frames`).
  - Under Proton / SteamOS, Windows `waveOut` API calls are translated by `winepulse.drv` to PipeWire, which pulls audio in fixed quantum periods (typically 1024 frames = 21.33 ms at 48 kHz).
  - The inharmonic relationship between the 16.67 ms (800-frame) VBlank generation tick, 256-frame blocks, and 1024-frame PipeWire batch pulls caused the intermediate device queue to deplete to zero intermittently, producing PipeWire XRuns (buffer underruns) heard as clicks/pops on engine waveforms.
  - Furthermore, `launcher/crates/gt4l-core/src/launch.rs` scrubbed all `GT4_*` variables, preventing Steam Deck users from overriding audio knobs via Steam Launch Options.
- Solution architecture:
  - Dynamic runtime Wine/Proton detection via `wine_get_version` in `ntdll.dll`.
  - When running under Wine/Proton, target latency auto-tunes to 100 ms (4800 frames) with twenty-four 512-frame buffers (10.67 ms each), providing $> 4.6$ PipeWire quanta of buffer headroom and completely eliminating XRuns.
  - Native Windows execution retains the exact 60 ms / 256-frame / 16-buffer baseline (100% bit-identical and zero added latency).
  - User customization supported via `GT4_AUDIO_LATENCY_MS` (20..500 ms).
  - Launcher pass-through: `GT4_PACING` and `GT4_AUDIO_LATENCY_MS` added to `PASSED_THROUGH` in `launch.rs`.
- Updated `TASKS.md`, `docs/ISSUE-TRIAGE.md`, and `docs/STATUS.md`.
