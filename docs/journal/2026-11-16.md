## TASK-077: Context-aware input mapping rebased and integrated on main

Branch `task/077-context-input-mapping`.

### Summary
Context-aware input mapping separating race and menu controls natively without guest code modification or translated unit changes.

- **VBlank Context Probe (`native/context_probe.{hpp,cpp}`):** Reads guest RAM at VBlank starting from owner pointer `0x622F4C`. Recognizes 10 race vtables (`RaceGTmode`, `RaceArcade`, `RaceFreeRun`, `RaceLicense`, etc.), attract mode `RaceArcadeDemo` (mapped to Menu), and pause objects at `race + 0xE418` (`RacePause`, `SimplePause`, `PhotoPause`). 3-frame debounce filter prevents state chatter.
- **Transition Filter (`native/context_input.{hpp,cpp}`):** Implements the re-arm rule (held keys across transitions are disarmed until physically released), clean switch frames (all buttons released on the switch frame), and loading screen neutral pad.
- **Controls Schema 2 (`native/controls.{hpp,cpp}`):** Supports `schema = 2` with `[bindings.<context>]` override tables (`race`, `pause`, `menu`, etc.) and full fallback to `[bindings]`. Built-in defaults map Esc to Start in races and Triangle in menus.
- **Integration with Wheel & Pad Input (`native/window.cpp`):** Integrated seamlessly with `WheelInput` device exclusion and button filtering in `on_vblank()`.
