# 2026-11-16

## Fix: Logitech G920 Force Feedback stopping / failing after session restart (Issue #243)

Branch `task/243-g920-ffb-restart`.

### Problem Analysis
Users reported that the Logitech G920 racing wheel worked on first launch, but Force Feedback stopped working completely on subsequent sessions or after restarting the game / reconnecting.

Investigation identified four root causes in `native/wheel.cpp`:
1. **Duplicate GUID disambiguation rejection:** On Windows, the Logitech G920 creates two device nodes in SDL3 sharing the identical USB GUID (`0300...6d04...c262...`): a DirectInput/RawInput wheel node (`is_wheel = true, is_gamepad = false`) with true FFB support, and an XInput gamepad wrapper node (`is_wheel = true, is_gamepad = true`) lacking DirectInput FFB. When `config.device_guid` was saved to `wheel.toml`, `select_primary_device` saw two devices matching the GUID and returned `-1` due to an ambiguous device check (`if (selected >= 0) return -1;`). This caused `primary_joystick_` and `primary_haptic_` to fail initialization entirely.
2. **Auto-detection node priority:** When `config.device_guid` was empty, `select_primary_device` previously took the first candidate matching `is_candidate_wheel_device`. If Windows enumerated the XInput wrapper node first, it picked that node where `SDL_OpenHapticFromJoystick` fails, resulting in 0 FFB.
3. **Shadow node GUID exclusion:** The shadow gamepad node was not added to `owned_device_ids_`, allowing `ControllerInput` to claim it as a standard gamepad and send rumble commands concurrently, interfering with wheel state.
4. **Driver gain zeroed on shutdown:** `WheelInput::close_haptic()` called `stop_haptic_output()` which set `gain = 0` and `autocenter = 0` immediately before closing the handle. Logitech Windows drivers persist this zeroed gain in hardware firmware across session restarts.

### Solution
1. In `select_primary_device()`, when multiple devices share the same GUID (or in auto-detect mode), prefer dedicated wheel nodes (`is_wheel && !is_gamepad`) over gamepad wrapper nodes, falling back to any candidate wheel device only if no dedicated node exists.
2. In `WheelInput::prepare()`, also exclude all device instances sharing the selected wheel's GUID from being picked up as general controllers by `ControllerInput`.
3. In `WheelInput::close_haptic()`, restore gain (100) and autocenter (100) before closing the SDL haptic handle so the wheel's firmware is never left muted.
4. In `WheelInput::open_haptic_for_primary()`, initialize gain to configured strength rather than zero.
5. In `WheelInput::apply_dfp_forces()`, update hardware autocenter when autocenter forces are active.
6. Added test coverage in `native/wheel_fixture.cpp` testing dual-node G920 selection in both explicit GUID and auto-detect modes across varying enumeration orders. All unit tests pass.
