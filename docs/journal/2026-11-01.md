# 2026-11-01

## TASK-057: modding scope, data patches, and GT4.VOL overlay architecture

- Completed comprehensive architectural study on modding scope ([`docs/TASK-057-MOD-SCOPE-STUDY.md`](../TASK-057-MOD-SCOPE-STUDY.md)) and ratified Decision 0073 ([`docs/decisions/0073-mod-scope-and-vol-overlay.md`](../decisions/0073-mod-scope-and-vol-overlay.md)).
- Evaluated community request Issue #87 (Cheats / .pnach support):
  - Formally closed as Not Planned. In GT4Recomp, EE code is statically recompiled ahead-of-time (AOT) into 326 C++ units (`unit_XXXX.cpp`). Guest RAM instructions are never executed by host CPU; MIPS writes are silent no-ops. Dynamic retranslation violates project no-JIT rules (`AGENTS.md`) and standalone distribution (`Decision 0069`). Freezing memory counters corrupts atomic save transactions (`sio2.cpp`) and desynchronizes 60 Hz physics loop (`RaceBase__updateRace`).
- Accepted `gs-preset` visual profiles for Release 1.1.0:
  - Validated bundles of `gs-settings.toml` rows managed in launcher mod store with zero executable changes.
- Formulated the Read-only `GT4.VOL` Virtual Sector Overlay (Phase 2 / Spec II / 1.1.0+):
  - Intercepts sector reads at the host `disc::read` hook (`disc.cpp:86`).
  - Serves an in-memory patched RoFS Table of Contents (TOC) and redirects modified file extents to loose mod files (`%LOCALAPPDATA%\GT4Recomp\mods\active\vol\`) without modifying the user's original disc image (`/GT4.VOL;1`).
  - Enables community Brazilian Portuguese translation (`rtext.rt2`), car physics tuning (`.cdat`), and HUD customization (`.gpb`) safely.
- Restricted RAM data patches to audited, typed native runtime contracts (Decision 0071 model).
- Updated `TASKS.md` (row 97 and `### TASK-057`), `docs/ISSUE-TRIAGE.md` (Issue #87), and `docs/STATUS.md`.
